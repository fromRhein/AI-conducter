# Brahms IV E113–311 articulation plan

Run `python -B render_work/articulation_plan.py`. Import `build_plan(root=None)` for a dictionary without writes or top-level execution. Requires existing `mido`. Source XML, MIDI and factory states are read only. The generator writes only `render_work/articulation_plan.json`.

## Schema: brahms-articulation-plan-v1

- `source_range_q`: `[384,1029)`, absolute source quarter-note positions, staff numbers 1–16. XML measure 113 = 384; score end = 1029.
- `notes`: one row per source MIDI note intersecting the excerpt, including stable `id` (staff:source attack ordinal), `staff`, `onset_q`, `offset_q`, `source_onset_q`, `pitch`, `velocity`, `source_channel`, `articulation`, `xml_match`, `xml_onset_q`, `xml_pitch`, `xml_voice`, `measure`, `reason`, `ornament_expansion`, `timpani_trill_as_roll_approximation`, and `preset_options`. No MIDI pitch transposition, added unisons, note merging or synthesized notes.
- `lane_events`: compact `staff,onset_q,pitch,id,articulation` rows. Route each note and its matching note-off to a fixed preset/articulation instance. This is a per-note lane assignment, not a monophonic global keyswitch timeline: simultaneous voices may use different articulations.
- `performance_nominal_on_tick/off_tick`: `round((source_q-384+1.5)*960)`, before the separate performance preparer's +/-4 ms onset-group shifts. Match using source note identity/tuple before humanization; carry lane identity through that step. Seconds require the conductor tempo map, including its fermata.
- `notation_events`: XML text, articulation signs, tremolo spans and slur spans intersecting the excerpt. Slurs may begin before 384. `inherited_text_events` preserves earlier pizz/arco changes; parser processes the entire score before excerpt filtering.
- `xml_notes`: notated notes, durations, voices, articulation signs, tremolo subtype, grace and tie-in flags. Ties are already merged by the source MIDI; XML notes are evidence, not another playable note list.
- `presets`: exact harvested factory root branches, recursively enumerated leaf `node_path`, titles and patch names; `articulation_root_indices`; `keyswitch_midi_notes: null`.
- `audit`: note and match counts, pitch-alignment evidence, measure and end positions.

## Deterministic assignment and approximations

Priority is persistent exact pizz/pizz. text, explicit Tremolo, explicit staccato/staccatissimo, inclusive slur, sustain. Arco clears pizz. Accent signs remain evidence and do not force Sforzato. Unmarked short durations do not automatically become staccato; existing MIDI gates remain intact. Slur endpoint attacks are included; polyphonic legato and transition overlap require audition. Shortened staccato export gates may be shorter than the sampled articulation and need musical review.

Timpani is exceptional: XML ornamentTrill is interpreted as a roll lane, explicitly flagged `timpani_trill_as_roll_approximation`. MuseScore exported alternating pitches, including 268 upper-neighbor attacks. For example source q492 has XML pitch52 with ornamentTrill, while MIDI includes pitch53 at q492.1229167. Those pitches and all repeated attacks remain in this plan. Rendering these directly through sustained Rolls samples can retrigger excessively and sound wrong. The parent should consciously choose either faithful MIDI attack reproduction or a separately documented notation-based roll reconstruction; do not silently combine both. String tremolos likewise have expanded source MIDI attacks; the plan adds none.

Cello text at q744.5 is `*1-arco\n2 pizz`; it is retained verbatim, not flattened into a staff-wide bow change. Voice-specific divisi interpretation is not resolved by this first-pass mapper. Review this passage using `xml_voice` and notation evidence.

## Paired-wind splitting without invented notes

Group by staff and onset, retaining source voice and each note's identity. When distinct XML voices represent the two players, route by voice with continuity. Otherwise route two simultaneous pitches high to player 1 and low to player 2, maintaining existing phrase continuity where possible. A single source note goes to one player only unless a separate, explicit doubling decision is made; `a 2` text is recorded evidence, not permission here to fabricate a second MIDI note. Two existing same-pitch notes remain two existing notes. Never duplicate every staff note onto both presets. More than two simultaneous notes or ambiguous crossing should be reported rather than discarded. Tenor trombone staff9 has only one harvested preset name; two instances can use it for existing two-voice material. Horn staffs6/7 each use the available Horn1/Horn2 colors; player 3/4 identities are an orchestration choice, not new notes.
